# WB-05: Refactor with invariant preservation

## Goal

Improve a small internal structure while preserving behavior exactly. This checks whether the worker can simplify code without semantic drift.

## Starting point

Parent provides:

- The smell or duplication to remove.
- The invariant that must remain true.
- Existing tests that cover the behavior.
- A maximum diff size or file count.

Good examples: extract a repeated parser helper, centralize a formatter branch, or remove dead fallback logic that tests prove unreachable.

## Allowed scope

Allowed:

- Refactor only the named internal surface.
- Add a missing characterization test before refactoring if coverage is weak.
- Rename private helpers when it makes the invariant clearer.

Forbidden:

- Changing public behavior, CLI output, serialized formats, or docs unless explicitly requested.
- Combining the refactor with feature work.
- Expanding abstractions beyond the repeated pattern.

## Verification

Required checks:

```bash
npm run test:unit -- <coverage-for-refactored-area>
npm run typecheck
```

The worker must state what invariant stayed unchanged and how the checks cover it.

## Scoring notes

This task primarily measures code quality under constraint. Score down for behavior drift, abstraction astronautics, churn across unrelated files, or refactors that make future changes harder.
