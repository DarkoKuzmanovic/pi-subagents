# WB-04: Test-writing and regression lock

## Goal

Add meaningful regression tests for an existing behavior gap, then make the minimal implementation change if the test exposes a bug. The worker must demonstrate test-first discipline.

## Starting point

Parent provides:

- The behavior that should be locked down.
- The existing test file or closest test pattern.
- The verification command for that test area.
- Whether implementation is expected to already pass or fail.

## Allowed scope

Allowed:

- Add focused tests in the existing test style.
- Use existing helpers and mocks.
- Patch implementation only after the new test fails for the expected reason.

Forbidden:

- Creating a duplicate test harness.
- Testing mocks instead of behavior.
- Weakening or deleting existing assertions.
- Adding implementation before showing the red test result.

## Verification

Required checks:

```bash
npm run test:unit -- <target-test-file>
npm run typecheck
```

The final response must include RED and GREEN evidence: the initial failure summary and the passing command summary.

## Scoring notes

This task primarily measures test quality and verification honesty. Score down for tests that pass before implementation, over-mocked tests, broad snapshots, skipped red evidence, or tests that assert implementation details instead of behavior.
