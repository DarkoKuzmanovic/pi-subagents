# WB-02: Spec-driven small feature

## Goal

Implement a small feature from a precise mini-spec. The feature should be user-visible or API-visible, but limited enough that a good worker can finish in one pass.

## Starting point

Parent provides:

- A 5-10 bullet mini-spec.
- Explicit non-goals.
- One target entry point or public API.
- At least one expected usage example.

Good examples: add one CLI flag, add one tool parameter, extend one serializer field, or add one validation branch.

## Allowed scope

Allowed:

- Edit the named entry point and directly-owned helpers.
- Add or update tests proving the new behavior.
- Update brief local docs only if the public behavior changed.

Forbidden:

- Redesigning surrounding architecture.
- Renaming public APIs unless explicitly requested.
- Adding dependencies.

## Verification

Required checks:

```bash
npm run test:unit -- <new-or-target-test-file>
npm run typecheck
```

The worker must include a short summary mapping each spec bullet to the implemented diff.

## Scoring notes

This task primarily measures instruction fidelity. Score down if the model implements adjacent nice-to-haves, changes semantics outside the spec, or forgets test coverage for the new behavior.
