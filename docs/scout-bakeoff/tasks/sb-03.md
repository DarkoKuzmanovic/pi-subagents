# SB-03: Test infrastructure handoff

## Goal

Produce a worker-ready summary of how to add a new unit test in this repository without accidentally using the wrong runner, loader, or import style.

## Starting point

Start from `package.json`, `test/support/`, and nearby unit tests.

## Allowed scope

Read-only inspection of `package.json`, `test/unit/`, `test/integration/`, `test/support/`, project instructions, and any test-related docs. Do not edit files.

## Expected evidence

A strong answer should cite the exact unit and integration test commands, Node loader differences, `.js` import convention for source imports, TypeScript strip/transform constraints, and common helper files.

## Scoring notes

Reward a concise checklist a worker can follow. Penalize recommending Jest/Vitest, omitting loader flags, or failing to mention source imports use `.js` extensions even though disk files are `.ts`.
