# SB-02: Async run recovery trace

## Goal

Explain how completed async/parallel runs are recovered when the runner process dies before writing an aggregated result.

## Starting point

Start from changelog notes about stale-run recovery, then trace the code path that reads async run state and decides whether a run can be salvaged.

## Allowed scope

Read-only inspection of `src/runs/background/`, `src/runs/shared/`, tests under `test/unit/` and `test/integration/` that cover async execution or stale-run reconciliation, plus `CHANGELOG.md`. Do not edit files.

## Expected evidence

A strong answer should cite the reconciler module, status/result artifacts involved, success/failure conditions, and at least one test or missing-test risk. It should say what data proves all steps are terminal.

## Scoring notes

Reward end-to-end flow and boundary conditions. Penalize hand-wavy recovery claims, missing failure cases, or invented file names.
