## Disagreements resolved

1. **Grok's security "blockers" vs the repo's trust model.** Grok rated B1 (relative-`..` output escape) and B3 (weak async resume validation) as High/blocking under an adversarial framing. The repo's threat model — stated in grok's own notes — is local same-UID: parent model and child agents already run with full user privileges and file-write tools, so path containment on the `output` param is not a security boundary. **Resolution:** downgraded both to SHOULD FIX (F14, F13) as isolation/consistency bugs, not exploits: F14 because silent pollution outside chainDir breaks the documented isolation contract (the repo's own CHANGELOG treats real-tree write leaks as bugs), F13 because the nested path already treats the identical input as untrusted and the async path should match. B2 (real-tree progress.md writes) stays SHOULD FIX on the same "documented bug class" basis. N2/N3 fell to IGNORED as intentional features.
2. **Opus C-3 marked blocking vs its own "dormant" qualifier.** Opus listed the gate-verdict validator among blocking findings while noting it is unreachable until gate is wired (its own C-2 proves no consumer exists). **Resolution:** moved to NOTE (O1) with an explicit trigger condition — it must be fixed before or with any M13.2 gate re-entry, and the fix choice for F3 (remove schema vs error out) determines its urgency. No reviewer contradicts the facts; only the severity framing conflicted.
3. **Opus N-8 vs `PLAN.md`.** Not a reviewer-vs-reviewer conflict but a reviewer-vs-repo-record one: PLAN.md's Deferred section records a `GateVerdict.note` defect that opus shows does not exist in the shipped tree. Oracle sides with opus (type, schema, and runtime all make `note` optional); resolution is the O6 doc correction.
4. **No verdict conflict.** All four reviewers independently returned request_changes; no finding from one reviewer was contradicted on the facts by another. Overlaps (result-watcher subsystem: opus N-6, k3 K3-N6, K3-N7) proved to be three distinct defects and were kept as separate items (F10, F11, O12).
