## Goal

Add per-dispatch `thinking` level control to the subagent API and `/subagents` TUI so one-off dispatches can override thinking without editing persistent agent definitions.

## Scope in

- Add optional `thinking` to single dispatch, chain steps, and parallel task objects.
- Preserve precedence: inline dispatch `thinking` > `agentOverrides.thinking` > agent file `thinking` > session default.
- Pass the effective level through foreground/background/chain execution to spawned Pi sessions.
- Add `/subagents` TUI selector that shows the effective thinking level, filters/handles levels supported by the selected model, and applies the selected level according to the hub's actual configuration semantics.
- Add tests for schema/type acceptance, precedence, runtime argument construction, and TUI dispatch behavior.

## Scope out

- Changing Pi core thinking-level semantics.
- Adding new thinking levels beyond `off`, `minimal`, `low`, `medium`, `high`, `xhigh`.
- Implementing unrelated model-provider or chain-clarify UX changes.
- Migrating historical `.pi/tasks/` artifacts.

## Acceptance criteria

- `subagent({ agent, task, thinking })` accepts valid thinking levels and uses the inline value for that dispatch only.
- Chain steps and parallel tasks accept `thinking` and propagate it to child sessions.
- Inline `thinking` wins over configured agent override/frontmatter; `off` is handled intentionally.
- `/subagents` shows the current effective thinking level and applies selected thinking coherently for its configuration-hub workflow.
- Unsupported levels for a selected model are not silently passed as invalid model suffixes.
- Unit/integration tests cover single, chain, parallel, and TUI paths.
- Relevant thinking-dispatch tests pass; `npm run typecheck` has no identified M0-specific failure but still reports broad pre-existing project errors.

## Phase boundary health

M0 leaves the extension in a coherent expected-green state: the new option is supported end-to-end in API, execution, TUI, and tests. Later milestones may refine UX, but M0 should not leave schema-only or TUI-only partial support.

## Constraints / invariants

- No implementation files are changed by this milestone plan.
- Runtime dependencies remain unchanged.
- Keep TypeScript strict style: no `any`, no new non-null assertions, type-only imports where needed.
- Use Node built-in test runner and existing support helpers.
- Preserve existing chain-clarify thinking behavior; share helpers only when it reduces duplication without broad refactor.
