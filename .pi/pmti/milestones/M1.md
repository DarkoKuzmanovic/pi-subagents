# M1 — Model lanes and JSON config shortcut

**Status:** Completed
**Planned date:** 2026-06-05
**Source:** User request — tighten visible subagent roster to six roles and add explicit model-lane routing before provider bakeoff.
**Workspace strategy:** current-branch
**Expected branch/worktree:** current orchestrator-selected branch/worktree; executors must stop on mismatch
**Workspace owner:** orchestrator

## Goal

Add explicit per-role model lanes and a JSON editor shortcut so bakeoff runs can route one logical agent role (especially `worker`) through `easy`, `medium`, and `hard` model choices without keeping duplicate role agents.

## Scope in

- Add a `subagents.modelLanes` settings shape for role/lane model routing.
- Add a `lane` dispatch override for single, chain, and parallel subagent execution.
- Preserve precedence: inline `model` / `thinking` > selected lane `model` / `thinking` > `agentOverrides` / builtin frontmatter > current session default.
- Add a `/subagents config` JSON shortcut that creates or opens the user settings file at `~/.pi/agent/settings.json`, seeds a safe `subagents.modelLanes` object when absent, and opens it in `$VISUAL`, `$EDITOR`, or a conservative fallback.
- Consolidate the default visible roster toward six durable roles: `recon`, `planner`, `worker`, `reviewer`, `oracle`, and `janitor`.
- Update docs/tests for the JSON shortcut, lane dispatch behavior, and roster consolidation.

## Scope out

- Full lane-editing TUI table inside `/subagents`.
- Automatic difficulty classification or auto-routing by task content.
- Provider bakeoff execution or model-quality conclusions.
- Removing agent files from the package; disabled/deprecated builtins can remain as compatibility artifacts.
- Changing Pi core model or thinking semantics.
- Reworking unrelated M0 thinking-level changes currently dirty in the working tree.

## Acceptance criteria

- `subagent({ agent: "worker", lane: "easy", task: "..." })` routes through the configured `worker.easy` lane.
- Chain steps and parallel tasks can specify `lane` and receive the lane's model/thinking values.
- Explicit inline `model` and/or `thinking` always override the corresponding lane field; partial lane configs work predictably.
- Unknown requested lanes fail with a clear error instead of silently falling back to a real provider.
- `/subagents config` is usable without TUI lane editing: it ensures user settings exist, preserves existing settings, initializes only missing `subagents.modelLanes`, and opens or reports the exact JSON file path.
- The executable agent list is reduced to the six durable roles via builtin override/default disable behavior, with compatibility docs for the disabled names.
- Tests cover lane parsing/precedence, slash shortcut behavior, and disabled-roster visibility.
- Relevant targeted tests pass; if broad `npm run typecheck` still reports pre-existing project errors, the executor records the exact evidence and verifies M1-specific files.

## Phase boundary health

M1 leaves the extension operational and coherent before the bakeoff: the public role surface is smaller, model routing is explicit and reproducible, and JSON editing provides a transparent control plane. Later milestones can add a richer lane-editing TUI without invalidating the JSON-backed lane model.
